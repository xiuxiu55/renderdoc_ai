# 使用 RenderDoc 源码进行内存 / 帧率(GPU 耗时)分析

本文档介绍如何**直接调用 RenderDoc 自身的源码 / API** 对一个 `.rdc` 捕获文件做程序化分析，重点是两类指标：

1. **GPU 耗时 / “帧率”**：每个绘制事件在 GPU 上的执行时间（`EventGPUDuration`）。
2. **显存 / 资源内存**：每个纹理、Buffer 占用的字节数。

> ⚠️ 先明确 RenderDoc 的定位与限制：
> - RenderDoc 是**单帧抓帧调试器**，它捕获的是**一帧**，因此**没有内置 FPS / 帧率计数器**。所谓“帧率分析”，实际做法是统计这一帧内各绘制事件的 GPU 耗时（`EventGPUDuration`，单位秒），求和/排序即可得到该帧的 GPU 时间热点。
> - RenderDoc **没有“显存总量”这种单一 API**。内存分析通过累加所有资源的字节大小得到（纹理 `byteSize` + Buffer `length`）。

分析有两条路径：

- **路径 A（推荐）：Python 脚本** —— 调用编译出的 `renderdoc` 模块（`renderdoc.pyd`）。开发快、无需写 C++。
- **路径 B：C++ 直接链接源码** —— 直接使用 `renderdoc/api/replay/renderdoc_replay.h` 里的接口，编译成独立程序。

---

## 1. 核心 API 一览

所有公开回放/分析 API 都在 `renderdoc/api/replay/` 下：

| 文件 | 作用 |
|------|------|
| `renderdoc/api/replay/renderdoc_replay.h` | 主接口：`IReplayController`、`ICaptureFile`、`RENDERDOC_OpenCaptureFile()` 等 |
| `renderdoc/api/replay/data_types.h` | 数据结构：`ActionDescription`、`TextureDescription`、`BufferDescription`、`CounterResult`、`FrameDescription` |
| `renderdoc/api/replay/replay_enums.h` | 枚举：`GPUCounter`、`ActionFlags`、`CounterUnit` 等 |
| `renderdoc/api/replay/control_types.h` | `ReplayOptions` 等 |

关键调用链（打开文件 → 拿到回放控制器）：

```
RENDERDOC_InitialiseReplay()        // 全局初始化（每进程一次）
  └─ RENDERDOC_OpenCaptureFile()    // 得到 ICaptureFile*
       └─ ICaptureFile::OpenFile()  // 载入 .rdc
            └─ ICaptureFile::OpenCapture()  // 得到 IReplayController*
```

`IReplayController` 上用于分析的主要方法（见 `renderdoc_replay.h`）：

```cpp
void                                  SetFrameEvent(uint32_t eventId, bool force);
FrameDescription                      GetFrameInfo();
const rdcarray<ActionDescription> &   GetRootActions();          // 绘制/事件树根节点
rdcarray<GPUCounter>                  EnumerateCounters();       // 硬件支持哪些计数器
CounterDescription                    DescribeCounter(GPUCounter counter);
rdcarray<CounterResult>               FetchCounters(const rdcarray<GPUCounter> &counters);
const rdcarray<TextureDescription> &  GetTextures();             // 所有纹理
const rdcarray<BufferDescription> &   GetBuffers();              // 所有 Buffer
const rdcarray<ResourceDescription> & GetResources();           // 资源元信息(含名字)
```

### 名字避坑（容易搜错）

| 你可能以为的名字 | 实际名字 |
|---|---|
| `GPUDuration` | `GPUCounter::EventGPUDuration` |
| `GetCounterData` | `FetchCounters()` |
| `DrawcallDescription` / `GetDrawcalls()` | `ActionDescription` + `GetRootActions()`，用 `ActionFlags::Drawcall` 判断 |
| “显存总量 API” | 无，需自己累加 `TextureDescription.byteSize` + `BufferDescription.length` |
| “FPS API” | 无，用逐事件 `EventGPUDuration` |

## 2. 关键数据结构

### GPU 耗时相关

`GPUCounter`（`replay_enums.h`）里 `EventGPUDuration = 1` 是通用计数器，所有后端都支持，单位为秒。

`CounterResult`（`data_types.h`）：每个 (事件, 计数器) 一条结果。

```cpp
struct CounterResult {
  uint32_t     eventId;
  GPUCounter   counter;
  CounterValue value;   // union: float f; double d; uint32_t u32; uint64_t u64;
};
```

取值时要看 `DescribeCounter().resultByteWidth`：8 字节用 `value.d`，4 字节用 `value.f`。`EventGPUDuration` 是 8 字节 double、单位 `CounterUnit::Seconds`。

### 内存相关

`TextureDescription`（`data_types.h`）关键字段：

```cpp
uint32_t     width, height, depth;
uint32_t     mips, arraysize, msSamp;
ResourceFormat format;
ResourceId   resourceId;
uint64_t     byteSize;   // 已包含所有 mip / 数组层 / MSAA 采样的总字节数
```

`BufferDescription`：

```cpp
ResourceId resourceId;
uint64_t   gpuAddress;
uint64_t   length;       // 字节数
```

`GetResources()` 返回的 `ResourceDescription` **不含字节大小**，但有 `resourceId` 和可读 `name`，可用于给上面两个表补充名字。

`GetFrameInfo()` 返回的 `FrameDescription` 里有**文件层面**的内存量（不是显存）：`uncompressedFileSize`、`compressedFileSize`、`persistentSize`、`initDataSize`。

## 3. 路径 A：Python 脚本分析（推荐）

### 3.1 前置：拿到 `renderdoc` 模块

在本仓库用 VS 构建后，模块位于：

```
x64\Development\pymodules\renderdoc.pyd
```

（构建命令见本仓库根说明；配置用 `Development` 或 `Release`，平台 `x64`。）

RenderDoc 的 Python 模块要求使用**与之匹配的 Python 版本**（本仓库自带 `qrenderdoc/3rdparty/python`，通常是 CPython 3.6）。运行脚本前需要让 Python 能找到 `renderdoc.pyd` 所在目录。

### 3.2 最小可运行示例

```python
import sys
sys.path.append(r"G:\renderdoc_ai111\x64\Development\pymodules")

import renderdoc as rd

# 1) 全局初始化
rd.InitialiseReplay(rd.GlobalEnvironment(), [])

# 2) 打开 .rdc 文件
cap = rd.OpenCaptureFile()
result = cap.OpenFile(r"C:\path\to\capture.rdc", '', None)
if result != rd.ResultCode.Succeeded:
    raise RuntimeError(f"打开文件失败: {result}")

if not cap.LocalReplaySupport():
    raise RuntimeError("当前机器不支持本地回放该捕获（缺少对应 GPU/驱动）")

# 3) 打开回放，得到 controller
result, controller = cap.OpenCapture(rd.ReplayOptions(), None)
if result != rd.ResultCode.Succeeded:
    raise RuntimeError(f"回放初始化失败: {result}")

# ====== 在这里做分析（见下文） ======

# 4) 清理（顺序很重要）
controller.Shutdown()
cap.Shutdown()
rd.ShutdownReplay()
```

### 3.3 帧率 / GPU 耗时分析

```python
def analyse_gpu_timing(controller, top_n=20):
    available = controller.EnumerateCounters()
    if rd.GPUCounter.EventGPUDuration not in available:
        print("该后端不支持 EventGPUDuration")
        return

    desc = controller.DescribeCounter(rd.GPUCounter.EventGPUDuration)
    results = controller.FetchCounters([rd.GPUCounter.EventGPUDuration])

    def seconds(r):
        return r.value.d if desc.resultByteWidth == 8 else r.value.f

    total = sum(seconds(r) for r in results)
    print(f"本帧 GPU 总耗时(各事件求和): {total * 1000:.3f} ms")
    if total > 0:
        print(f"该帧近似 GPU 上限帧率: {1.0 / total:.1f} FPS")

    print(f"\n最耗时的 {top_n} 个事件:")
    for r in sorted(results, key=seconds, reverse=True)[:top_n]:
        print(f"  EID {r.eventId:<6}  {seconds(r) * 1000:.4f} ms")
```

> “近似上限帧率”只是把这一帧的 GPU 时间取倒数，用于粗略判断 GPU 侧瓶颈，不等于真实运行帧率（真实帧率还受 CPU、垂直同步、驱动排队等影响，而 RenderDoc 抓帧本身也会引入开销）。

### 3.4 内存 / 资源分析

```python
def analyse_memory(controller, top_n=20):
    # 资源名字表：resourceId -> name
    names = {res.resourceId: res.name for res in controller.GetResources()}

    textures = controller.GetTextures()
    buffers = controller.GetBuffers()

    tex_total = sum(t.byteSize for t in textures)
    buf_total = sum(b.length for b in buffers)

    def mb(x):
        return x / (1024.0 * 1024.0)

    print(f"纹理数量: {len(textures)}  合计: {mb(tex_total):.2f} MB")
    print(f"Buffer 数量: {len(buffers)}  合计: {mb(buf_total):.2f} MB")
    print(f"资源内存总计: {mb(tex_total + buf_total):.2f} MB\n")

    print(f"最大的 {top_n} 个纹理:")
    for t in sorted(textures, key=lambda t: t.byteSize, reverse=True)[:top_n]:
        name = names.get(t.resourceId, str(t.resourceId))
        print(f"  {mb(t.byteSize):8.2f} MB  {t.width}x{t.height} "
              f"mips={t.mips} arr={t.arraysize}  {name}")

    print(f"\n最大的 {top_n} 个 Buffer:")
    for b in sorted(buffers, key=lambda b: b.length, reverse=True)[:top_n]:
        name = names.get(b.resourceId, str(b.resourceId))
        print(f"  {mb(b.length):8.2f} MB  {name}")
```

### 3.5 遍历绘制事件

绘制不是单独的类型，而是带 `ActionFlags.Drawcall` 标志的 `ActionDescription` 节点，从 `GetRootActions()` 拿到根、递归 `children`：

```python
def walk_actions(controller):
    def recurse(action, depth=0):
        if action.flags & rd.ActionFlags.Drawcall:
            indent = "  " * depth
            name = action.GetName(controller.GetStructuredFile())
            print(f"{indent}EID {action.eventId}: {name} "
                  f"(indices={action.numIndices}, instances={action.numInstances})")
        for child in action.children:
            recurse(child, depth + 1)

    for root in controller.GetRootActions():
        recurse(root)
```

如果要查询某个事件时刻的管线状态、读取资源内容，需要先 `controller.SetFrameEvent(eventId, False)` 把回放状态移动到该事件之后，再调用 `GetPipelineState()` / `GetBufferData()` / `GetTextureData()`。

### 3.6 组合成完整脚本

把 3.2 的骨架和 3.3~3.5 的函数拼在一起即可：

```python
analyse_gpu_timing(controller)
print("\n" + "=" * 60 + "\n")
analyse_memory(controller)
```

## 4. 路径 B：C++ 直接调用源码

若要写独立 C++ 程序（链接 `renderdoc.dll` / `renderdoc.lib`），核心头文件是 `renderdoc/api/replay/renderdoc_replay.h`。

```cpp
#include "api/replay/renderdoc_replay.h"

int main()
{
  GlobalEnvironment env;
  RENDERDOC_InitialiseReplay(env, {});

  ICaptureFile *cap = RENDERDOC_OpenCaptureFile();
  ResultDetails res = cap->OpenFile("capture.rdc", "", NULL);
  if(!res.OK()) { /* 处理错误 */ }

  if(!cap->LocalReplaySupport().OK()) { /* 不支持本地回放 */ }

  ReplayOptions opts;
  rdcpair<ResultDetails, IReplayController *> ret = cap->OpenCapture(opts, NULL);
  if(!ret.first.OK()) { /* 处理错误 */ }
  IReplayController *controller = ret.second;

  // ---- GPU 耗时 ----
  rdcarray<GPUCounter> avail = controller->EnumerateCounters();
  if(avail.contains(GPUCounter::EventGPUDuration))
  {
    CounterDescription desc = controller->DescribeCounter(GPUCounter::EventGPUDuration);
    rdcarray<CounterResult> results =
        controller->FetchCounters({GPUCounter::EventGPUDuration});
    double total = 0.0;
    for(const CounterResult &r : results)
      total += (desc.resultByteWidth == 8) ? r.value.d : (double)r.value.f;
    printf("本帧 GPU 总耗时: %.3f ms\n", total * 1000.0);
  }

  // ---- 内存 ----
  uint64_t texBytes = 0, bufBytes = 0;
  for(const TextureDescription &t : controller->GetTextures())
    texBytes += t.byteSize;
  for(const BufferDescription &b : controller->GetBuffers())
    bufBytes += b.length;
  printf("纹理: %.2f MB, Buffer: %.2f MB\n",
         texBytes / 1048576.0, bufBytes / 1048576.0);

  // ---- 遍历绘制 ----
  // 递归 controller->GetRootActions()，用 (action.flags & ActionFlags::Drawcall) 判断

  controller->Shutdown();
  cap->Shutdown();
  RENDERDOC_ShutdownReplay();
  return 0;
}
```

实现细节可参考：
- `renderdoc/replay/capture_file.cpp` —— `CaptureFile::OpenCapture()` 的真实实现。
- `renderdoc/replay/replay_controller.cpp` —— `FetchCounters` / `EnumerateCounters` 的转发实现。
- `renderdoc/driver/d3d12/d3d12_counters.cpp` —— `EventGPUDuration` 的语义与计算方式（时间戳差 / 频率）。

## 5. 常见问题

- **`LocalReplaySupport()` 返回失败**：捕获来自不同 API/GPU（例如在 A 卡上回放 N 卡专属捕获），或缺少对应驱动。
- **`EnumerateCounters()` 里没有厂商计数器**：`EventGPUDuration` 等通用计数器一定有；`FirstAMD`/`FirstNvidia`/`FirstIntel` 段的计数器需要对应厂商 GPU + 驱动扩展。
- **纹理 `byteSize` 与实际显存占用有差异**：`byteSize` 是各子资源理论字节数之和，不含驱动对齐/tiling 等开销，用于横向对比资源大小足够。
- **Python 报模块加载错误**：多半是 Python 版本与 `renderdoc.pyd` 不匹配，或没把 `pymodules` 目录加进 `sys.path`。
